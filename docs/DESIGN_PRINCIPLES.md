# Design Principles

## Purpose

These principles define the long-term visual direction of the product.

They are independent of implementation details, frameworks and technologies.Every design decision—from early concepts to production implementation—should reinforce these principles.

The goal is not to create a visually impressive website. The goal is to communicate professional experience with clarity, confidence and as little friction as possible.

---

# Core Philosophy

The product is first and foremost a communication tool.

Design exists to support understanding rather than persuasion.

The interface should communicate engineering confidence through restraint, clarity and attention to detail.

---

# Progressive Disclosure

Present only the information required for the current decision.

Allow visitors to explore deeper only when they choose to.

The homepage should introduce the professional profile, not tell the entire career story.

Every page should answer:

- What is this?
- Why does it matter?
- Where should I go next?

---

# Content First

Content is the primary interface.

Every visual decision should improve readability, hierarchy or comprehension.

Avoid decorative elements that distract from the content or interrupt reading flow.

---

# Typography First

Typography is the primary design tool.

Hierarchy should be created through typography, spacing and alignment before introducing colour, borders or visual containers.

A well-designed page should remain effective in grayscale.

If colour is removed, the information hierarchy should remain immediately understandable.

---

# Editorial Design

The portfolio should feel closer to a premium technical publication than a marketing website.

Layouts should encourage reading rather than scanning for visual effects.

Use generous whitespace, consistent rhythm and clear section hierarchy to guide the reader naturally through the content.

Avoid landing-page patterns whose primary purpose is persuasion rather than communication.

---

# Whitespace

Whitespace is a layout tool.

Use spacing to create hierarchy, rhythm and focus rather than relying on borders, backgrounds or shadows.

Content should have room to breathe.

---

# Visual Hierarchy

The most important information should be immediately visible.

Visitors should naturally understand:

1. Who this portfolio belongs to.
2. What the primary professional focus is.
3. Why the work is worth exploring.
4. How to continue.

Navigation should support the content, never compete with it.

---

# Content Density

Prefer concise sections with clear separation over dense blocks of information.

Allow whitespace to reduce cognitive load and improve scanning.

Readers should be able to understand the overall structure before deciding what to read in depth.

---

# Colour

The interface should remain predominantly monochromatic.

Use a restrained neutral palette for almost all interface elements.

Introduce a single accent colour to communicate emphasis, interaction and navigation.

Use OKLCH colour values to achieve predictable contrast and consistent visual intensity while avoiding oversaturated or artificial-looking colours.

Colour should support hierarchy, never replace it.

---

# Components

Components exist to organise content, not decorate it.

Keep them visually quiet.

Avoid unnecessary cards, badges, icons, borders and visual treatments that add hierarchy without adding meaning.

Consistency should emerge from reusable patterns rather than visual complexity.

---

# Icons

Icons should support recognition rather than replace labels.

Avoid decorative iconography.

Use icons only when they improve comprehension or speed of recognition.

---

# Motion

Motion should communicate interface state.

Use subtle transitions for:

- hover;
- focus;
- expanding content;
- navigation feedback.

Avoid decorative animation or movement that distracts from reading.

---

# Accessibility

Accessibility is a design requirement.

Ensure:

- clear visual hierarchy;
- sufficient colour contrast;
- keyboard accessibility;
- visible focus states;
- responsive layouts;
- readable typography.

Accessibility should be considered from the first design iteration rather than added later.

---

# Responsive Design

Design for content rather than devices.

Layouts should adapt naturally across screen sizes while preserving hierarchy, rhythm and readability.

Avoid device-specific layouts when responsive composition solves the problem.

---

# Consistency

Maintain consistent spacing, typography, colours and interaction patterns throughout the site.

Consistency should emerge from a small set of reusable rules rather than duplicated styling or component variations.

---

# Visual Tone

The portfolio should feel:

- modern;
- understated;
- editorial;
- technically confident;
- intentional;
- approachable.

It should resemble a well-crafted technical publication more than a marketing website.

---

# Avoid

Do not rely on:

- large illustrations;
- decorative gradients;
- glassmorphism;
- excessive cards;
- unnecessary icons;
- decorative patterns;
- visual effects without purpose;
- animation as decoration;
- multiple accent colours.

When in doubt, remove rather than add.

---

# Design Evaluation

Before accepting a design, ask:

- Does the content remain the focus?
- Is the visual hierarchy immediately clear?
- Would the layout still work in grayscale?
- Does every visual element have a clear purpose?
- Does the interface feel calm rather than busy?
- Does the design communicate seniority, clarity and attention to detail?
- Would this design still feel appropriate in five years?

If the answer to any of these questions is no, simplify the design before adding new elements.

---

# Product Before Marketing

The interface should feel like a thoughtfully designed software product rather than a personal marketing website.

Interaction patterns should prioritise usability, comprehension and engineering quality over visual novelty.

The goal is to build trust through thoughtful execution rather than visual persuasion.
